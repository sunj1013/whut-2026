①作用域与局部变量

变量只在自己那对花括号里有效，出去就"消失"。

先看真实的报错现场：for 里的 i、函数里的 num。

②全局变量

写在所有函数外面，默认初值 0。

能带回多个结果，也会带来副作用——能不用就不用。

③变量存储类型

auto / static / register / extern：存在哪、活多久。

static 局部只初始化一次，函数退出值还在。

④内部与外部函数

static 函数只本文件可见，extern 可跨文件调用。

多文件工程里，这两个关键字决定"谁能调谁"。

贯穿主线先问"变量写在哪对花括号里"（作用域），再问"加没加 static"（生存期）。两问答对，绝大多数"变量莫名变值 / 找不到"的错都能定位。
本讲学习目标

  • ② 生存期说清一个变量"活多久"，知道它什么时候被销毁
  • ③ 排错用作用域规则解释"未定义标识符"这类报错
  • ④ 全局变量知道它的默认初值、副作用与使用边界
  • ⑤ 存储类型分清 auto / static / register / extern 的差别
  • ⑥ 跨文件说清内部函数与外部函数的可见范围
先看一段"看着对"的代码
int main() {
    int n;
    scanf("%d", &n);
    for(int i=2; i<=(int)sqrt(n); i++) {
        if(n%i==0) break;
    }
    if(i>sqrt(n))
        printf("%d是素数", n);
    else
        printf("%d不是素数", n);
    return 0;
}
编译器怎么说
报错error: 'i' undeclared (first use in this function)

i 明明在第 5 行刚刚定义过，为什么编译器说它"不存在"？

先记住变量不是"写到过"就一直有效——它只在自己的一小块地盘里有效。这块地盘，就叫作用域。
7.7　变量的作用域：变量在哪儿有效

变量有效性的范围，称为变量的作用域。

函数外部定义的

叫 全局变量（Global variable）
整个文件中多处都能用

函数内部定义的

叫 局部变量（Local variable）
只在自己那个函数／块里能用

一句话写在哪里，决定它管多大一片地方——写在函数里，就只管这个函数；写在所有函数外面，才管整个文件。
局部变量：块内定义，块内有效
凡是满足这两条的，都是局部变量
  • 在函数内定义整个函数里都能用
  • 在复合语句内定义只在那一对 {} 里能用
界限作用域以外，这个变量不能被引用——写了就是语法错误。
例7-9　两个同名的 x
int main(){
    int x=10;
    printf("x=%d\n",x);
    if(x>0){
        int x;          // 又一个 x
        x=-10;
        printf("x=%d\n",x);
    }
    printf("x=%d\n",x);
    return 0;
}
例7-9：同一个名字，两个不同的变量
运行结果
x=10 x=-10 x=10
关键中间那个 -10，住在 if 的花括号里；出了这对花括号，它就不存在了。外面那个 x 从头到尾没被碰过，一直是 10。
逐条对上
第 1 条第 3 行输出：此时只有函数里的 x=10。
第 2 条if 块里新定义一个 x，赋 -10 并输出。这个 x 只在 {} 内有效，但它盖住了外面那个。
第 3 条出了 if 块，块里的 x 已经"消失"，输出又回到外面的 x=10。
关于局部变量，要记住三条
  • ① 主函数不外借main 里定义的变量只能在 main 里用；反过来，main 也用不了别的函数里定义的变量。
  • ② 形参也算局部形参变量属于被调函数的局部变量；实参变量属于主调函数的局部变量。
  • ③ 同名不打架不同函数里可以有同名变量，它们代表不同对象、分配不同单元，互不干扰，也不会混淆。
印证例7-9 里那两个 x 就是"同名不打架"的最小例子——名字一样，占的不是同一个单元。

三块领地各自为政：谁家的变量，只有谁看得见
调 f1 时，f1 的 a、b、c 才被建出来；f1 一返回，它们就没了
对上前两页的错那个 i 报错，是因为它站在 for 那块小领地外面；那个 num 报错，是因为 SumA 这块领地里压根没有它。不是写错了，是站错了地方。
名字一样，单元不同
int f1(){
    int n=1;
    return n;
}
int f2(){
    int n=100;
    return n;
}
内存里是这样
f1 的 n单独一块单元，存 1。
f2 的 n另一块单元，存 100。

两块单元地址不同，改谁都不影响另一个。C 编译器只在自己函数的范围里找名字，所以不会找错。

一句话同名不等于同一个——名字只在自己那块领地里有效，出了这道门，它就是另一个变量了。
错在哪：i 只活在 for 的括号里
✗ 原来如此：
for(int i=2; i<=sqrt(n); i++)
    if(n%i==0) break;
if(i>sqrt(n))     // i 已不存在
    printf("%d是素数", n);
结果编译不通过：'i' undeclared
✓ 改成这样
int i;
for(i=2; i<=sqrt(n); i++)
    if(n%i==0) break;
if(i>sqrt(n))     // i 仍在
    printf("%d是素数", n);
结果通过。i 定义在函数里，for 结束后还活着，还能拿来判断"是循环走完的，还是 break 跳出来的"。
结论for(int i=…) 里的 i，作用域只有 for 那一对括号加循环体。想在外面接着用，就得把 i 定义到外面去。
错在哪：这个 num 从哪儿来？

    int flag=0;

        flag += num;      // num ？
    }

}
a.c:23:15: error: 'num' undeclared 23 | flag+=num; | ^~~
学生心里的想法

"我在别的地方写过 num，这里应该能用吧？"

不行SumA 的函数体里没有 num 的定义，外面也没有全局的 num——编译器在 SumA 这块领地里找不到它，只能报错。
记住一个函数只能看见：自己的局部变量 + 全局变量 + 自己的形参。三样都没有，就是没有。
怎么改：让数据从参数进来
int fn(int a,int n){          // 求 a+aa+…+a
    int s=0;
    for(int i=0;i<n;i++)  s=s*10+a;
    return s;
}
int SumA(int a,int n){        // 前 n 项之和
    int s=0;
    for(int i=1;i<=n;i++)  s+=fn(a,i);
    return s;
}
三个变量，各在各家
fn 的 s只属于 fn
SumA 的 s只属于 SumA
两个 i各在各的 for 里，互不相干
要点函数之间只通过参数和返回值交换数据。想用一个数，就把它当参数传进来，别指望"外面有"。
全局变量：写在所有函数外面
两条要点
定义凡在函数外部定义的变量，称全局变量（也叫外部变量）。
范围它的作用域从定义位置开始，到本源文件结束——注意，是"从定义处往下"，不是"整个文件"。
推论写在程序最前面，所有函数都能用；写在中间，只有它后面的函数能用。
位置决定谁能用
int p=1, q=5;        // ← 从这里开始有效
float f1(int a){
    return a+p;      // ✓ 能用
}
char f2(int x){
    return x+q;      // ✓ 能用
}
int main(){
    p=3;              // ✓ 能用
    return 0;
}
例7-10　用全局变量交换两个数
#include <stdio.h>
int x,y;                  // 全局，初值都是 0
void swap(){
    x=x+y;  y=x-y;  x=x-y;
}
int main(){
    x=3, y=7;
    swap();               // 没有参数
    printf("x=%d y=%d\n",x,y);
    return 0;
}
运行结果
x=7 y=3
为什么行swap 一个参数都没有、一个 return 都没有，却把 main 的 x、y 换掉了——因为它俩是全局的，两个函数看的是同一块内存。
对比之前讲参数传递时，swap(int a,int b) 怎么都换不成。差别就在：那是各拿各的副本，这是共用同一对变量。
全局变量不写初值，也不是"乱码"

没有指定初值时，全局变量自动取该类型的系统默认值：

数据类型默认初值说明
int0整型零
float / double0.0浮点零
char'\0'空字符，编码值 0
指针NULL空指针
对照局部变量没赋初值时是随机的垃圾值；全局变量是可靠的 0。这是两类变量在"寿命"上的第一个差别。
例7-11　一次带回四个结果（1/2）
#include <stdio.h>
int s1,s2,s3;              // 全局：三个面积
int vs(int a,int b,int c){
    int s1,s2,s3;          // ← 这里又定义了一遍
    int v;
    v=a*b*c;
    s1=a*b;  s2=b*c;  s3=a*c;
    return v;
}
这一页先看 vs

体积 v 用 return 交回去；三个面积想通过全局变量 s1、s2、s3 交回去。

问题函数据第 4 行又定义了一份 s1、s2、s3。从这一行起，函数里说的 s1 是它自己那个，赋值全赋给了局部变量，全局的那三个一点没动。
这叫屏蔽：内层同名变量把外层同名变量挡在外面。
例7-11　一次带回四个结果（2/2）
int main(){
    int s1,s2,s3;          // ← main 也来一份
    int v,l,w,h;
    scanf("%d%d%d",&l,&w,&h);
    v=vs(l,w,h);
    printf("v=%d,s1=%d,s2=%d,s3=%d\n",
           v,s1,s2,s3);
    return 0;
}
输入 3 4 5 的运行结果
v=60,s1=-858993460, s2=-858993460,s3=-858993460
没带回来体积对了（return 起效），三个面积打出来是 -858993460 这种怪数——main 里这三个也没赋过值，打印的是内存里残留的垃圾（换台机器就变别的数）。这正是第 15 页说的「局部变量不赋初值就是垃圾值」。
三个地方各一份全局一份、vs 里一份、main 里一份。名字一样，各写各的：vs 算完写进自己那份，main 打的是自己那份（从没算过），全局那份一动没动。
屏蔽：内层同名，外层就"看不见"了
判断口诀看这行代码写在哪个函数里：函数里定义过 s1，用的就是函数里那份；函数里没有，才轮到全局的。函数之间互不相干——vs 的 s1 和 main 的 s1 是两个变量，谁也不包含谁。
去掉两处局部声明，就通了
int s1,s2,s3;                // 只留全局这一份
int vs(int a,int b,int c){
    int v=a*b*c;
    s1=a*b;  s2=b*c;  s3=a*c;
    return v;
}
int main(){
    int v,l,w,h;
    scanf("%d%d%d",&l,&w,&h);
    v=vs(l,w,h);
    printf("v=%d,s1=%d,s2=%d,s3=%d\n",v,s1,s2,s3);
    return 0;
}
输入 3 4 5
v=60,s1=12,s2=20,s3=15
通了vs 改的是全局的 s1、s2、s3，main 打印的也是同一份——四个结果一次带回。
代价这份"能带回多个值"的能力，是靠全局变量人人可见换来的。用多了，就是下一张幻灯片要说的麻烦。
全局变量的两面：能传值，也有副作用

好的一面：能带回多个结果

函数只能 return 一个值。想把好几个结果交回主调函数，可以让函数去改全局变量。

例7-11 就是这么干的：体积用 return 带回，三个面积交给全局的 s1、s2、s3。

坏的一面：改了大家都知道

全局变量在某个函数里被改了，其它函数看到的也跟着变。

哪一行改的？谁改的？查起来非常麻烦——这就是副作用。下一页看一个最小的例子。

回头看例7-11 想用全局变量带回三个面积，先撞上「屏蔽」；把重复声明去掉之后，还得防着这一面——副作用。
一句话全局变量像一块公告栏：谁都能看、谁都能改——省事，也容易出事。
副作用：i 被另一个函数偷偷改了
#include<stdio.h>
int i;                       // 全局
int main() {
    void prt();
    for(i=0; i<5; i++)
        prt();
    return 0;
}
void prt() {
    for(i=0; i<5; i++)
        printf("%c",'$');
    printf("\n");
}
本意 vs 实际
本意打印 5 行，每行 5 个 $。
$$$$$
实际只打印了一行。
为什么prt 里的 for 用的也是全局 i。它跑完，i 变成了 5；回到 main，i++ 变成 6，循环条件 6<5 不成立，直接结束。
7.7 收口　什么时候才用全局变量
代价　能不用就不用 这时才用它
① 加大系统开销
整个运行期都占内存，函数返回也不释放。		 一次要带回多个结果
return 只能交回一个，例7-11 是四个。
② 降低可读性
一个函数改了它，另一个函数的结果莫名其妙就变了。		 全程序共用一份数据
配置、计数器：改了就得处处同步。
③ 降低通用性
函数从「给参数、出结果」变成「还依赖外面某个变量」。		 层层传参太啰嗦
中间好几层都得带着它走，才考虑。
做法优先用参数传数据、用 return 带回结果；确实要多值返回，再考虑全局变量或指针。
补一句要在全局变量定义之前用它，就先 extern 声明一下——7.8 节讲。
作用域小结：一张表说清
对比项局部变量全局变量
定义位置函数内、复合语句（块）内所有函数之外
作用范围所在的块或函数从定义处到本源文件结束
默认初值不确定（垃圾值）0 / 0.0 / '\0' / NULL
同名时内层优先，屏蔽外层被同名局部变量屏蔽
函数返回后消失仍然存在，值保留
一句话收口变量只管自己那一块地盘；名字撞了，里层说了算。
7.8　变量的存储类型：先看内存怎么分
两块地方，两种活法
静态放在静态存储区的变量叫静态变量，例如全局变量。程序一启动就分配，运行结束才收回。
动态放在动态存储区的变量叫动态变量，例如函数形参、局部变量，以及调用时的现场保护和返回地址。函数一调用才分配，一返回就收回。
记住作用域管"谁能用"，存储类型管"活多久、放哪儿"。
用这张图写程序时问自己两句：这个变量要活多久？——决定它进静态区还是动态区；要谁能看见？——决定写成全局还是局部。
一个变量，两个属性

C 语言里每个变量都有两个属性：数据类型和数据的存储类别。完整的变量定义要把两种属性都写出来：

存储类别符　数据类型符　变量表;

auto　自动类别

默认值。不写存储类别，就是它。

register　寄存器类别

把变量放进 CPU 寄存器，图个快。

static　静态类别

函数返回后不消失，值留着。

extern　外部类别

声明"这个变量在别处已经定义过"。

接下来四种类别逐个看：auto → register → static → extern。
auto：默认的那个；register：塞进寄存器

auto 变量

函数里的局部变量，如果不专门声明，都是动态分配存储空间的，放在动态存储区，这类叫自动变量。

用关键字 auto 声明，它也是存储类别的默认值。

auto int b=0;   // 等同于
int b=0;

注意：不赋初值时，它是随机值。

register 变量

为了提高效率，C 允许把局部变量的值直接放在 CPU 寄存器里，这种变量叫寄存器变量。

用关键字 register 声明。

register int i, sum;

注意：寄存器变量不能取地址（没有内存地址），所以不能写 &i。

什么时候用auto 是常态，绝大多数局部变量都是它；register 只用在"循环里反复用、次数特别多"的少数几个变量上，现在的编译器往往比我们更会安排，写了也只是个建议。
例7-12　static：函数走了，它还在
#include<stdio.h>
int f(int a) {
    auto int b=0;      // 每次进来重新来
    static int c=3;    // 只初始化一次
    b++;  ++c;
    return(a+b+c);
}
int main() {
    int i;
    for(i=1;i<4;i++)
        printf("f(%d)=%d\n",i,f(i));
    return 0;
}
运行结果
f(1)=6 f(2)=8 f(3)=10
看这里a 每次不同（1、2、3），b 每次都从 0 变成 1，只有 c 一路涨上去：4 → 5 → 6。
为什么b 是 auto，函数一返回就消失；c 是 static，放在静态存储区，函数返回后还留着。
三次调用，c 一直往上加
调用a（形参）b（auto）c（static）返回 a+b+c
f(1)10 → 13 → 41+1+4 = 6
f(2)20 → 14 → 52+1+5 = 8
f(3)30 → 15 → 63+1+6 = 10
a 的命形参，每次由调用者递一个新值（1、2、3），返回就丢。
b 的命 · 每次重来每次进函数都重新出生一次，初值 0，加 1 之后就被丢掉。
c 的命 · 留住只在第一次进函数时初始化为 3，之后一直住在静态存储区，谁调都加它。
一句话三行里 a、b 每次都是新的，只有 c 接着上一次的值——差别不在写法，在它住在哪块存储区。
静态局部变量：两条硬规矩

① 不赋初值，自动是 0

静态变量没写初值时，系统自动赋 0（数值型）或 '\0'（字符型）。

不会像 auto 变量那样是随机垃圾值。

② 赋初值只执行一次

那句 static int c=3; 里的 =3，整个程序运行期间只做一次。

以后再进这个函数，c 保持上次留下来的值，不会再被改回 3。

常见的误解"我每次都写 static int c=3，它应该每次都是 3 吧？"——不是。初值只在编译时准备好、程序启动时放进静态区，函数调用时跳过这条赋值。
什么时候用想让局部变量"记住上一次的值"时用：比如统计某个函数被调用过多少次。
extern：先用后定义
#include <stdio.h>
int main(){
    extern int s;      // 声明：s 在别处定义
    printf("%d\n", s);
    return 0;
}
int s=100;              // 定义在这，靠后
100
声明 ≠ 定义
定义分配内存，比如 int s=100;
声明不分配内存，只是告诉编译器"有这么个变量，类型是这个，在别的地方定义过"。

全局 s 的作用域本来是"从定义处到文件末"。加了 extern int s; 之后，main 里也能用了——作用域被往前扩了一截。

同一条理变量可以这么声明，函数也可以：这就是之前讲的函数声明。
习题一　static 的 k，输出什么？
#include <stdio.h>
int s;
int f(int m) {
    static int k=0;
    for(; k<=m; k++) s++;
    return s;
}
int main(void) {
    int s=1;
    s=f(2)+f(2);
    printf("%d#%d#",s,f(20));
    return 0;
}
选项
A6#21#
B9#27#
C32#32#
D26#26#
看解析

全局 s=0；main 里 int s=1; 是局部，把全局盖住。
第一次 f(2)：k 从 0 开始，循环 k=0,1,2 三圈，全局 s 变 3，k 停在 3，返回 3。
第二次 f(2)：k 还是 3（static 留住），3<=2 不成立，一圈没走，返回 s=3。
于是 s=3+3=6。
f(20)：k 从 3 到 20 共 18 圈，全局 s 从 3 加到 21，返回 21。
输出 6#21#，选 A。

习题二　把 static 去掉，答案变不变？
#include <stdio.h>
int s;
int f(int m) {
    int k=0;          // 少了 static
    for(; k<=m; k++) s++;
    return s;
}
int main(void) {
    int s=1;
    s=f(2)+f(2);
    printf("%d#%d#",s,f(20));
    return 0;
}
选项
A6#21#
B9#27#
C32#32#
D26#26#
看解析

k 变成 auto，每次进函数都重新置 0。
第一次 f(2)：走 3 圈，全局 s 变 3，返回 3。
第二次 f(2)：k 又是 0，再走 3 圈，s 变 6，返回 6。
于是 s=3+6=9。
f(20)：k 从 0 到 20 共 21 圈，s 从 6 加到 27，返回 27。
输出 9#27#，选 B。
对照上一题：就差一个 static，k 记不记住，答案完全不同。

7.9　函数也有作用域：内部函数与外部函数

函数默认可以被同一个程序的其他源文件调用。加上 static，就把它锁在本文件里。

内部函数（static）

只能被本文件里的其他函数调用，别的源文件调不到。

声明方式：

static 类型 函数名(参数表);

外部函数（extern）

既能被本文件调用，也能被其他源文件调用。不写时默认就是外部函数。

声明方式：

extern 类型 函数名(参数表);
为什么要分一个大工程由很多人分头写。写工具函数的同学不想让别人乱调自己的内部实现，就加 static——这和变量加 static 是一个思路：把可见范围收窄。
同一个工程，谁能调谁
一句话加 static 的函数出不了本文件；不加（或写 extern）的，别的文件声明一下就能用。而 #include 只是把声明搬过来——< > 找系统目录，" " 先找本工程。
本章要点回顾
  • 作用域变量有效性的范围。写在函数里是局部，写在所有函数外是全局。
  • 局部变量块内或函数内有效；同名不同函数互不干扰；形参属于被调函数。
  • 全局变量从定义处到文件末有效；默认初值为 0；能带回多个值，但也带来副作用，要限制使用。
  • 屏蔽内层同名变量挡住外层，写的是谁就改谁——例7-11 三个 s1 就是教训。
  • 存储类型auto 默认、register 进寄存器、static 留住值、extern 往前扩作用域。
  • 函数的作用域static 锁在本文件（内部函数），extern 或默认可跨文件（外部函数）。
